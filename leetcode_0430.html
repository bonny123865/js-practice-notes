小知識先補充一下

clearTimeout 與 setTimeout 的運行機制

setTimeout 會執行兩項動作：
1. 將非同步任務（回呼函式）註冊進執行環境內部的計時器管理表（Timer Table）。
2. 立即回傳一個唯一識別碼。在瀏覽器環境中，這個回傳值通常是一個正整數（例如 1, 2, 3…）；在 Node.js 中，它則是一個包含多種屬性的物件。
> 然後這邊可以說一下，他會接收兩個參數，第一個會是callback function，第二個會是設定的時間

clearTimeout 的唯一功能是根據傳入的 ID，要求執行環境去計時器管理表中搜尋對應的紀錄：
1. 若任務尚未執行：環境會將該任務從管理表中移除，使其永遠不會被觸發。
2. 若任務已經執行或 ID 不存在：執行環境找不到對應紀錄，因此不會發生任何動作，也不會報錯。

這邊有一個簡單的範例

console.log("開始註冊...");

// 註冊一個 5 秒後才執行的任務
const id = setTimeout(() => {
    console.log("執行中");
}, 5000);

// 此時 id 已經被賦予了一個整數（例如 1）【這邊註解一下】
console.log("註冊成功，獲取的 Timer ID 為：", id); 

// 若要在 5 秒內取消該計畫，只需將該 id 變數傳入
clearTimeout(id); 

console.log("已執行 clearTimeout，計畫已取消。");

請實作一個名為 createResettableTimer 的函式。此函式接收一個字串 message 與延遲時間 delay（毫秒），並回傳一個新的箭頭函式。

核心邏輯：如果在等待的 delay 毫秒內，這個新函式「又被呼叫了一次」，你必須使用 clearTimeout 取消上一次尚未執行的計時器，並重新啟動一個全新的計時器重新倒數。

    };

這邊對於這一個題目的解讀來說，我覺得比較會有困惑的點在於 因為會需要清除上一次計時器的ID，但是我要如何知道上一個計時器的ID??

Gemini : 就是使用Closure的概念就可以做到了！然後他有給我三個提示
1. 在外部當中要宣告的變數要是用 let ，因為每一次計時器的ID在重新呼叫的時候都會需要被overwrite，所以說要用 let 來做宣告，這樣內部的 arrow function 才可以持續使用這一個外部變數
2. 有關於 return 【內部函式】當中會需要做的東西，會需要先執行 clearTimeout(timerId)
因為 closure的特性，他會先去讀取外部的共用變數 timerId，然後因為第一次呼叫的時候會是 clearTimeout(undefined)，所以說不會引發錯誤
3. 然後清除完成之後，會需要設定新的計時器(因為先把舊的清除掉了)，設定新的還有讓他印出 message，然後在來把新計時器的ID賦值給外面的 timerId，這樣下一次呼叫的時候，timerId儲存的就會是下一次的舊ID

賦值的小誤解QQ

這邊說一下三個的順序，但是在說明順序之前，會先需要跟自己再說一次有關賦值的東西：
我們已知createResettableTimer是一個函式，所以說當我們寫const trigger = createResettableTimer("觸發！", 1000);的時候
createResettableTimer會return的東西是一個箭頭函式，所以說 trigger 他被賦值到的東西就會是那一個arrow function
所以說我們後續如果寫 trigger的話，就是在呼叫內部的() =>{XXX} 的內容

return 當中會需要設計的東西是什麼

題目的目的是說”當新函式被再次呼叫的時候，會需要先取消上一次尚未執行的，然後再重新啟動一個計時器” 所以說 在return 的部分，我會需要設計的東西有兩個【「清除舊 ID → 產生新任務 → 儲存新 ID 以備下次清除】
第一：會是需要先用clearTimeout
第二：會需要再多做一個計時器，所以我們可以先做setTimeout，然後因為下一次呼叫的時候timerId會需要儲存這一個計時器的ID，所以說我做完setTimeout之後再賦予值給timerId，這樣第三次呼叫trigger()的時候，我會儲存的就會是本次的timerId 以下是一小段的舉例

// 假設環境配發的計時器 ID 依序為 11, 22, 33
const trigger = createResettableTimer("觸發！", 1000); 
// 初始狀態：timerId 為 undefined

// 【第一次呼叫】 trigger()
// 1. 執行 clearTimeout(undefined)：靜默通過。
// 2. 執行 setTimeout：背景開始倒數 1000ms。系統回傳 ID 為 11。
// 3. 賦值：timerId 被更新為 11。

// 【第二次呼叫】 trigger() （假設在第 300 毫秒時發生）
// 1. 執行 clearTimeout(11)：成功攔截並取消第一次的任務。
// 2. 執行 setTimeout：背景重新開始倒數 1000ms。系統回傳 ID 為 22。
// 3. 賦值：timerId 被更新為 22。

// 【第三次呼叫】 trigger() （假設在第 600 毫秒時發生）
// 1. 執行 clearTimeout(22)：成功攔截並取消第二次的任務。
// 2. 執行 setTimeout：背景重新開始倒數 1000ms。系統回傳 ID 為 33。
// 3. 賦值：timerId 被更新為 33。

// 若後續不再呼叫，最終只會在第三次呼叫的 1000 毫秒後，印出一次 "觸發！"。

【1】 const trigger = createResettableTimer("觸發！", 1000);
>> 會先執行一次 createResettableTimer，這時候有傳入參數跟他預計的時間
這時候會關注兩個部分
第一：timerId：這時候會是 undefined，因為這是第一次呼叫到這一個東西，所以剛開始會先預設是undefined 第二：return：這邊會是需要被完成的一部分，然後因為我們把這一個呼叫createResettableTimer賦予給 trigger，所以說 trigger會收到的是 createResettableTimer 最後return 的東西

【2】 trigger();
這是它第一次被呼叫。它進到 return 的區塊內： 執行 clearTimeout(timerId)。因為是第一次，timerId 是 undefined，所以什麼事都沒發生。 執行 timerId = setTimeout(…)。這時候，系統在背景開始了一個 1000 毫秒的倒數（預計在第 1000 毫秒印出）。並把這組倒數的 ID 存進了 timerId。

【3】 setTimeout(() => trigger(), 500);
這代表會在0.5秒之後呼叫trigger 因為他的時限比較快到，所以說0.5秒之後，啟動了 () => trigger() 所以說trigger 被第二次呼叫了！它再次進到 return 的區塊內：
> 執行 clearTimeout(timerId)。這時候 timerId 裡面存著第 0 秒設定的那個 ID。於是，原本預計在第 1000 毫秒要印出的計畫，在這裡被直接砍掉了。
> 執行 timerId = setTimeout(…)。系統在背景重新開始了一個新的 1000 毫秒倒數（預計在 500 + 1000 = 第 1500 毫秒印出）。並把新的 ID 存進 timerId。

第二個練習第一次

createResettableTimer = (message, delay) => {
    // 所以說為了需要可以做到取消上一次尚未執行的計時器，所以會需要先儲存計時器的ID
    // 後續才可以把它做清除
    let timerId; 
    
    return () => {
        // 這邊會需要實作的東西是：在等待 delay 毫秒後，使用 console.log 印出 message
        clearTimeout(timerId)
        timerId = setTimeout(() =>{
            console.log(message)
        },delay)
    };
};

setTimeout(() => trigger(), 500);
